# Final project · ប្រព័ន្ធ Food Rescue របស់អ្នក

នៅសប្ដាហ៍ទី 2–8 អ្នកបង្កើតផ្នែកនីមួយៗនៃប្រព័ន្ធព័ត៌មានមួយ។ នៅសប្ដាហ៍ទី 9–10 អ្នកផ្គុំវាបញ្ចូលគ្នា ជា **ប្រព័ន្ធផ្ទាល់ខ្លួនរបស់អ្នក**។ វាដំណើរការសំណើផ្ដល់អាហារពេញមួយថ្ងៃ ធ្វើតាមការសម្រេចចិត្ត **របស់អ្នក** ហើយអ្នកអាចពន្យល់ និងប្រគល់ជម្រើសនីមួយៗបាន។ អ្វីៗទាំងអស់ធ្វើក្នុង notebook តែមួយ: `Final_Project.ipynb`។

## គំនិតសម្រាប់កម្រិតទី 3

- `pickup_label` ឬ `urgency` ដែលឆ្លាតជាងមុន ដោយប្រើ value មួយទៀតដែលអ្នកសម្រេច (ជាមួយ constant ដែលមានឈ្មោះ)។
- `clean_offer` ដែលតឹងរ៉ឹងជាងមុន ដែលបដិសេធអ្វីមួយថ្មី ជាមួយសារច្បាស់លាស់។ ចាប់ផ្ដើមពីការពិនិត្យរបស់ kit ផ្ទាល់ (`fr.validation.clean_offer`) ហើយបន្ថែមវិធានមួយ; notebook បង្ហាញពីរបៀបធ្វើ។
- លេខដែលស្មោះត្រង់មួយ ដូចជា `rejected_or_cancelled_percent(records)`: ភាគរយនៃសំណើដែលត្រូវបានបដិសេធ ឬលុបចោល។
- status ថ្មីមួយ ដូចជា `"reserved"` ក្នុង `ALLOWED_MOVES` ផ្ទាល់ខ្លួនរបស់អ្នក និងអ្នកណានឹងប្រើវា។ ដែនកំណត់ដែលដឹងហើយ: របាយការណ៍របស់ kit ស្គាល់តែ status ទាំង 6 ដូច្នេះសំណើដែល reserved បាត់ពីទិដ្ឋភាពអ្នកសម្របសម្រួល។ សរសេរ test មួយដែលបង្ហាញរឿងនេះ ហើយសរសេរវាក្នុងកំណត់ចំណាំប្រគល់ការងាររបស់អ្នក។
