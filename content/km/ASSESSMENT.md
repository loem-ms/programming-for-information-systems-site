# ការវាយតម្លៃ

វគ្គសិក្សានេះវាយតម្លៃអ្វីដែលអ្នក **យល់ បង្កើត test និងពន្យល់បាន**។ ភាគរយពិន្ទុខាងក្រោម គឺជា **ផែនការដែលបានស្នើ**។ គ្រូនឹងបញ្ជាក់វាជាមួយសាកលវិទ្យាល័យ មុនពេលការវាយតម្លៃចាប់ផ្ដើម។ ថ្ងៃផុតកំណត់តាមប្រតិទិន និងឈ្មោះ file នឹងប្រកាសនៅក្នុងថ្នាក់។

| ផ្នែក | ភាគរយ | អ្វីដែលរាប់ពិន្ទុ |
|---|---:|---|
| ការចូលរួម | 10% | ចូលរួមសកម្មភាពក្នុងថ្នាក់ និងបំពេញ form ការឆ្លុះបញ្ចាំង (reflection) ប្រចាំសប្ដាហ៍ |
| កិច្ចការស្រាវជ្រាវចំនួន 6 | 30% | 5% ក្នុងមួយកិច្ចការ: ប្រភពឯកសារ ឧទាហរណ៍ជាក់ស្ដែងមួយ និងការវែកញែករបស់អ្នកផ្ទាល់ |
| Midterm ធ្វើម្នាក់ឯង (សប្ដាហ៍ទី 4) | 30% | អាន សរសេរ និង test code; វាយតម្លៃ code ដែល AI សរសេរ; ពន្យល់ការសម្រេចចិត្តមួយ |
| Final project (សប្ដាហ៍ទី 9–10) | 30% | ប្រព័ន្ធរបស់អ្នកដែលដំណើរការបាន ការសម្រេចចិត្តរបស់អ្នក ការផ្ទៀងផ្ទាត់ ការប្រគល់ការងារ និងបទបង្ហាញ |
| **សរុប** | **100%** | |

**ដាក់ស្នើ (submit)** តាម email ទៅ [submit.progmis@gmail.com](mailto:submit.progmis@gmail.com) លើកលែងតែគ្រូប្រកាសវិធីផ្សេង។ សូមរក្សាទុកច្បាប់ចម្លងផ្ទាល់ខ្លួន នៃអ្វីៗទាំងអស់ដែលអ្នកដាក់ស្នើ។

សូមអានទំព័រនេះ នៅពេលចាប់ផ្ដើមវគ្គសិក្សា។ សូមអានវាម្ដងទៀត មុនពេល midterm និងមុនពេល Final project។ ផ្នែកខាងក្រោម រៀបតាមលំដាប់នៃវគ្គសិក្សា៖ ការចូលរួមរៀងរាល់សប្ដាហ៍ កិច្ចការស្រាវជ្រាវ midterm និង Final project។

## ការចូលរួម (10%)

ចូលរួមសកម្មភាពក្នុងវគ្គទី 1–3៖ ការទាយមើល ការងារជាគូ ការពិភាក្សា "ល្អ ឬមានហានិភ័យ?" និងការចាប់ផ្ដើមថ្នាក់។ ក្រោយរៀងរាល់សប្ដាហ៍ សូមបំពេញ [form ការឆ្លុះបញ្ចាំងប្រចាំសប្ដាហ៍](COURSE_LINKS.md)។ ប្រសិនបើខ្វះ form មួយ គ្រូនឹងសួរតាមដាន។ វាមិនរាប់ជាអវត្តមានដោយស្វ័យប្រវត្តិទេ។

## កិច្ចការស្រាវជ្រាវ (30%)

កិច្ចការខ្លីៗ 6 ដែលមួយៗមាន 5%។ កិច្ចការនីមួយៗភ្ជាប់គំនិតរបស់សប្ដាហ៍មួយ ទៅនឹងប្រព័ន្ធពិតមួយ។ មើល [កិច្ចការស្រាវជ្រាវ](RESEARCH.md) សម្រាប់ប្រធានបទ និងកាលវិភាគ។

| លក្ខណៈវិនិច្ឆ័យ | ពិន្ទុ |
|---|---:|
| ឧទាហរណ៍ដែលពាក់ព័ន្ធ និងប្រភពដែលមានឈ្មោះច្បាស់ យ៉ាងហោចណាស់មួយ | 1 |
| ការពន្យល់ត្រឹមត្រូវ ជាពាក្យរបស់អ្នកផ្ទាល់ | 1 |
| ករណីជាក់ស្ដែងមួយ (ឧទាហរណ៍ ករណីព្រំដែន (edge case) ឬ field ពិតមួយ) | 1 |
| ការវែកញែករបស់អ្នក រួមទាំងដែនកំណត់មួយ ឬសំណួរមួយដែលមិនទាន់មានចម្លើយ | 1 |
| ភស្តុតាងច្បាស់លាស់ រួមទាំងរបៀបដែលអ្នកពិនិត្យចម្លើយរបស់ AI | 1 |
| **សរុប** | **5** |

អនុញ្ញាតឱ្យប្រើឧបករណ៍ AI សម្រាប់ការស្រាវជ្រាវ។ ប្រសិនបើអ្នកប្រើវា សូមពិនិត្យការអះអាងយ៉ាងហោចណាស់មួយ ដោយខ្លួនឯង។ សូមប្រាប់ថា អ្នកពិនិត្យដោយរបៀបណា។ និស្សិតដែលមិនប្រើ AI ក៏អាចទទួលបានពិន្ទុពេញដូចគ្នា។

## Midterm (30%)

បន្ទាប់ពីការចូលរួមប្រចាំសប្ដាហ៍ និងកិច្ចការស្រាវជ្រាវ midterm គឺជាផ្នែកដំបូង ដែលអ្នកធ្វើទាំងស្រុងដោយខ្លួនឯង។

**ពេលណា:** សប្ដាហ៍ទី 4 វគ្គទី 3 (**60 នាទី** ប្រឡងម្នាក់ឯង + **30 នាទី** រៀបចំ ដាក់ស្នើ និងពិភាក្សាចម្លើយ)។ **ការចូលប្រឡង:** [ទំព័រ Midterm](MIDTERM.md) (លេខកូដ PIN ប្រកាសក្នុងថ្នាក់)។ **ធ្វើម្នាក់ឯង។** អនុញ្ញាត៖ កំណត់ចំណាំរបស់អ្នក notebook ប្រចាំសប្ដាហ៍ និង notebook Python Basics។ **មិនអនុញ្ញាត៖** ឧបករណ៍ AI ការផ្ញើសារ ឬការចែករំលែក code។

Midterm ពិនិត្យ **ការយល់ដឹង** ពីសប្ដាហ៍ទី 1–4 នៅក្នុងបរិបទប្រចាំថ្ងៃថ្មីមួយ (**តុបណ្ណាល័យសាកលវិទ្យាល័យ**) មិនមែនការចងចាំទេ។

| ផ្នែក | កិច្ចការ | ពិន្ទុ |
|---|---|---:|
| 1 | អាន និងតាមដានកូដដោយដៃ (type, loop trace, `print` ធៀបនឹង `return`, records) | 24 |
| 2 | ប្រែក្លាយដ្យាក្រាមលំហូរ (flowchart) ទៅជា function វិធាន (`loan_action`) + ពន្យល់ការផ្លាស់ប្ដូរវិធាន | 24 |
| 3 | ធ្វើការជាមួយ records៖ `desk_summary(loans)` បញ្ជូនត្រឡប់មកវិញ (return) នូវ dictionary សេចក្ដីសង្ខេប | 28 |
| 4 | ត្រួតពិនិត្យ តេស្ត និងកែសម្រួល code ដែល AI សរសេរ (`most_overdue_id`) + របាយការណ៍ផលប៉ះពាល់ | 24 |
| ចុងបញ្ចប់ | **បន្ទាត់សំខាន់របស់ខ្ញុំ** (ចាំបាច់ត្រូវបំពេញ) + clean run | ចាំបាច់ |

ក្រោយពេលអ្នកដាក់ស្នើ មាន **ការពិនិត្យផ្ទាល់មាត់ខ្លី 2–3 នាទី**៖ គ្រូសួរអំពី **បន្ទាត់សំខាន់របស់ខ្ញុំ** និងបន្ទាត់ ឬ test មួយទៀតក្នុង notebook របស់អ្នក។ ប្រសិនបើអ្នកមិនអាចពន្យល់ code ផ្ទាល់ខ្លួនរបស់អ្នកបានទេ ពិន្ទុនៃផ្នែកនោះ អាចត្រូវកាត់បន្ថយ។

## Final project (កំពុងធ្វើបច្ចុប្បន្នភាព) (30%)

ផ្នែកចុងក្រោយ ផ្គុំវគ្គសិក្សាទាំងមូលបញ្ចូលគ្នា នៅសប្ដាហ៍ទី 9–10។ នៅសប្ដាហ៍ទាំងនោះ អ្នកផ្គុំផ្នែកដែលអ្នកបានបង្កើត ឱ្យក្លាយជាប្រព័ន្ធផ្ទាល់ខ្លួនរបស់អ្នក។

មើល មគ្គុទ្ទេសក៍ Final project (កំពុងធ្វើបច្ចុប្បន្នភាព) សម្រាប់កម្រិតទាំង 4 និងអ្វីដែលត្រូវដាក់ស្នើ។

| អ្វីដែលត្រូវវាយតម្លៃ | ភាគរយក្នុង project |
|---|---:|
| **វាដំណើរការបាន ហើយបានផ្ទៀងផ្ទាត់:** កម្រិតទី 1, clean run, `verify()` បង្ហាញថាដំណើរការត្រឹមត្រូវ | 25% |
| **ការសម្រេចចិត្តរបស់អ្នក:** settings នៅកម្រិតទី 2 និងគុណភាពនៃកំណត់ត្រាការសម្រេចចិត្ត (decision log) | 30% |
| **Test និងការពង្រីក:** test សម្រាប់ការសម្រេចចិត្តរបស់អ្នក (ត្រូវតែមាន) + កម្រិតទី 3 / កម្រិតទី 4 (ស្រេចចិត្ត) | 15% |
| **ការប្រគល់ការងារ:** កំណត់ចំណាំប្រគល់ការងារ និងកំណត់ត្រា peer test | 15% |
| **បទបង្ហាញ និងការពន្យល់ផ្ទាល់ខ្លួន** (សប្ដាហ៍ទី 10) | 15% |

ការបញ្ចប់កម្រិតទី 1 និង 2 បានល្អ ជាមួយ test ពីរសម្រាប់ការសម្រេចចិត្តរបស់អ្នក កំណត់ចំណាំប្រគល់ការងារច្បាស់លាស់ និងបទបង្ហាញមួយ គឺគ្រប់គ្រាន់សម្រាប់និទ្ទេសល្អ។ កម្រិតទី 3 និង 4 បន្ថែមពិន្ទុ។ ប៉ុន្តែ កម្មវិធីកុំព្យូទ័រវែង ដែលមានការសម្រេចចិត្តខ្សោយ ទទួលបានពិន្ទុទាបជាងកម្មវិធីកុំព្យូទ័រខ្លី ដែលមានការសម្រេចចិត្តរឹងមាំ និងពន្យល់បានច្បាស់។

## យុត្តិធម៌ និងភាពស្មោះត្រង់

វិធានយុត្តិធម៌ដដែលនេះ អនុវត្តចំពោះគ្រប់ផ្នែកខាងលើ។
