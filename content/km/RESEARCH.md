# កិច្ចការស្រាវជ្រាវ

កិច្ចការខ្លីៗចំនួនប្រាំមួយ **5% ក្នុងមួយកិច្ចការ** (សរុប 30%)។ R1 និង R2 យកគំនិតរបស់សប្ដាហ៍មួយ ចេញពី notebook ទៅមើលក្នុងប្រព័ន្ធពិតមួយដែលអ្នកស្គាល់។ R3–R6 នីមួយៗបង្រៀនអ្នកអំពី **គោលគំនិតមួយនៃការសរសេរកម្មវិធី (programming concept)** ដែលអ្នកត្រូវការនៅសប្ដាហ៍បន្ទាប់៖ ដំបូងអ្នក **អាន** អំពីវា បន្ទាប់មក **សួរ** AI អំពីចំណុចដែលអ្នកនៅមិនទាន់យល់ច្បាស់ រួច **ពិនិត្យ** ចំណុចមួយដោយ run កូដ ហើយចុងក្រោយ **សម្រេចចិត្ត**៖ អ្នកបញ្ចេញមតិផ្ទាល់ខ្លួន ចំពោះសំណួរមួយដែលគ្មានចម្លើយត្រឹមត្រូវតែមួយ។

ទំព័រនេះជាទំព័រយោង សម្រាប់កិច្ចការស្រាវជ្រាវទាំងអស់។ សូមបើកវាទុក រាល់ពេលដែលអ្នកចាប់ផ្ដើមកិច្ចការមួយ។ លក្ខណៈវិនិច្ឆ័យដាក់ពិន្ទុ មាននៅក្នុងទំព័រ [ការវាយតម្លៃ](ASSESSMENT.md)។

## R1 · ប្រព័ន្ធព័ត៌មានពិតមួយ

*ពី [សប្ដាហ៍ទី 1 · តើប្រព័ន្ធព័ត៌មានជាអ្វី?](notebooks/Week_01.ipynb)។*

ចូរជ្រើសរើសប្រព័ន្ធមួយ ដែលអ្នកធ្លាប់ប្រើ ដូចជា ការចុះឈ្មោះចូលរៀន, app ឡានក្រុង ឬ app ទិញសំបុត្រ, បណ្ណាល័យ, ជួររង់ចាំនៅមន្ទីរពេទ្យ ឬ app ផ្ទេរប្រាក់តាមទូរស័ព្ទ (mobile money)។ តើនរណាជាអ្នកប្រើប្រាស់វា (យ៉ាងហោចណាស់តួនាទីពីរ)? តើវារក្សាទុកទិន្នន័យអ្វីខ្លះ? ចូរប្រាប់វិធានមួយ ដែលវាអនុវត្តតាម។ ចូរប្រាប់រឿងមួយដែលអាចនឹងខុសឆ្គង និងប្រាប់ថានរណានឹងរងផលប៉ះពាល់។

## R2 · វិធាន និងករណីព្រំដែន (edge case)

*ពី [សប្ដាហ៍ទី 2 · វិធាន និងការសម្រេចចិត្ត](notebooks/Week_02.ipynb)។*

ចូរជ្រើសរើសវិធានមួយពីជីវិតពិត ដូចជា ថ្លៃឡានក្រុងសម្រាប់កុមារ, ប្រាក់ពិន័យពេលសងសៀវភៅបណ្ណាល័យយឺត, កញ្ចប់ data ទូរស័ព្ទ ឬពិន្ទុជាប់ប្រឡង។ ចូរសរសេរវាឱ្យបានច្បាស់លាស់ តាមរបៀបដែលកម្មវិធីកុំព្យូទ័រមួយត្រូវការ។ ចូរផ្ដល់ករណីធម្មតា (normal case) មួយ ករណីព្រំដែន (edge case) មួយ (ស្មើនឹងកម្រិតកំណត់គត់) និងករណីចម្លែកមួយ (តម្លៃបាត់ ជាលេខអវិជ្ជមាន ឬមិនធម្មតា)។ តើនរណាជាអ្នកសម្រេចវិធាននេះ? ហើយតើនរណានឹងរងផលប៉ះពាល់ ប្រសិនបើចំណុចព្រំដែនត្រូវបានកំណត់ខុស?

## R3–R6 · ជំហានទាំងប្រាំ: អាន សួរ ពិនិត្យ សម្រេចចិត្ត

R3, R4, R5 និង R6 ធ្វើតាមជំហានប្រាំដូចគ្នា។ អ្វីដែលអ្នកដាក់ស្នើ មានប្រវែងប្រហែលមួយទំព័រ។

1. **អាន និងរៀបចំគំនិត។** ចូរអានផ្នែកនៃ [Python Basics](notebooks/Python_Basics.ipynb) ដែលមានឈ្មោះក្នុងកិច្ចការរបស់អ្នក និងជំពូក **មួយ** ពីបញ្ជីសៀវភៅសម្រាប់កិច្ចការរបស់អ្នក (សៀវភៅទាំងនេះអាចអានលើអ៊ីនធឺណិតដោយឥតគិតថ្លៃ សូមមើល [link របស់វគ្គសិក្សា](COURSE_LINKS.md))។ បន្ទាប់មក ចូរសរសេរសេចក្ដីសង្ខេបមួយជាពាក្យរបស់អ្នកផ្ទាល់ ប្រវែង 5–8 ប្រយោគ៖ វាជាអ្វី ហេតុអ្វីបានជាត្រូវការវា វាដំណើរការយ៉ាងដូចម្ដេច និងកំហុសមួយដែលគេជួបញឹកញាប់។ ចូរបន្ថែមឧទាហរណ៍តូចមួយ ដែលអ្នកបាន run ផ្ទាល់ ព្រមទាំងលទ្ធផល (output) របស់វា។
2. **សួរ AI អំពីចំណុចដែលនៅមិនទាន់ច្បាស់។** ចូរសួរជំនួយការ AI (AI assistant) អំពីផ្នែកដែលអ្នកមិនទាន់យល់ច្បាស់។ ចូរសួរ **សំណួរបន្ត (follow-up question) យ៉ាងហោចណាស់ពីរ**៖ មួយសុំឧទាហរណ៍ពីជីវិតប្រចាំថ្ងៃនៅកម្ពុជា ហើយមួយទៀតសួរថា *"តើមានអ្វីអាចនឹងខុសឆ្គង?"* ចូរចម្លង **បន្ទាត់សំខាន់ៗ 6–10 បន្ទាត់** នៃការសន្ទនានោះ ដាក់ក្នុងអ្វីដែលអ្នកដាក់ស្នើ៖ សំណួររបស់អ្នក និងផ្នែកដែលមានប្រយោជន៍បំផុតនៃចម្លើយ។
3. **ប្រៀបធៀប និងពិនិត្យ។** ចូររកកន្លែងមួយ ដែល (1) សៀវភៅ និង AI និយាយរឿងដូចគ្នា តែតាមរបៀបខុសគ្នា (2) សៀវភៅ និង AI និយាយរឿងខុសគ្នា ឬ (3) AI ឆ្លើយមិនច្បាស់ ឬឆ្លើយខុស។ បន្ទាប់មក ចូរសាកល្បងការអះអាង (claim) មួយ ដោយ run ឧទាហរណ៍តូចមួយនៅក្នុង Colab។ ចូរបង្ហាញកូដ និងលទ្ធផល។ តើការអះអាងនោះត្រឹមត្រូវឬទេ?
4. **មតិរបស់អ្នក។** ចូរសរសេរ **ប្រហែលកន្លះទំព័រ (≈ 150–250 ពាក្យជាភាសាអង់គ្លេស)** អំពីសំណួរសម្រាប់ជជែកពិភាក្សា។ ចូរជ្រើសរើសជំហរមួយ ហើយផ្ដល់មូលហេតុ។ ចូរប្រើឧទាហរណ៍មួយពី Campus FoodBridge។
5. **ប្រភព និងភាពស្មោះត្រង់។** ចូរប្រាប់ឈ្មោះផ្នែក និងជំពូកដែលអ្នកបានអាន ព្រមទាំងឧបករណ៍ AI ដែលអ្នកបានប្រើ។

## R3 · បញ្ហា (error) និង exception

*ពី [សប្ដាហ៍ទី 4 · Functions ដែលអាចទុកចិត្តបាន · file ដំបូងរបស់អ្នក · Midterm](notebooks/Week_04.ipynb)។*

**គោលគំនិត:** តើបញ្ហា (error) មួយ ឬ **exception** នៅក្នុង Python ជាអ្វី? តើមានអ្វីកើតឡើងចំពោះកម្មវិធីកុំព្យូទ័រ នៅពេល exception មួយកើតឡើង ហើយតើកម្មវិធីអាច **ចាប់ (catch)** វាបានដោយរបៀបណា?

- **អាន:** Python Basics ផ្នែក "08 · ការអានសារ error" និង "09 · `try`/`except` (និង `raise`)"។ បន្ទាប់មក ជំពូកមួយ៖ PY4E "Conditional execution" (ផ្នែកដែលនិយាយអំពីការចាប់ exception) ឬ "Errors and Exceptions" នៃមេរៀន Python ផ្លូវការ (official tutorial)។
- **សួរ (ឧទាហរណ៍):** *"ខ្ញុំបានអានថា `except` ចាប់ error។ តើមានអ្វីកើតឡើងចំពោះផ្នែកដែលនៅសល់នៃកម្មវិធី បន្ទាប់ពីនោះ?"* រួចសួរបន្ត ដើម្បីសុំឧទាហរណ៍ពីជីវិតប្រចាំថ្ងៃនៅកម្ពុជា (ទម្រង់បែបបទ (form) មួយ ហាងមួយ ឬ app ទូរស័ព្ទមួយ) និងសួរថា *"តើមានអ្វីអាចនឹងខុសឆ្គង ប្រសិនបើកម្មវិធីចាប់គ្រប់ error ទាំងអស់ ហើយបន្តដំណើរការទៅមុខ?"*
- **ពិនិត្យ (ឧទាហរណ៍):** ចូរ run `int("abc")` និង `int("12")`។ តើបន្ទាត់ទីមួយឈប់ ដោយបង្ហាញ error ដែលសៀវភៅ និង AI បានពិពណ៌នាឬទេ? បន្ទាប់មក ចូរដាក់វានៅក្នុង `try:` និង `except ValueError:`។ តើកម្មវិធីបន្តដំណើរការទៅមុខឬទេ?
- **មតិរបស់អ្នក:** *តើកម្មវិធីកុំព្យូទ័រគួរគាំង ឬបន្តដំណើរការដោយស្មានយកចម្លើយមួយ?*

## R5 · អ្វីដែលកើតឡើងចំពោះទិន្នន័យ នៅពេលដាច់ភ្លើង

**គោលគំនិត:** តើកម្មវិធីកុំព្យូទ័ររក្សាទុកទិន្នន័យរបស់វានៅឯណា ពេលវាកំពុងដំណើរការ ហើយតើអ្វីខ្លះបាត់បង់ នៅពេលដាច់ភ្លើង? តើ **file**, ទម្រង់ file (file format), **មូលដ្ឋានទិន្នន័យ (database)** និង **backup (ទិន្នន័យបម្រុងទុក)** ជួយបន្ថែមអ្វីខ្លះ?

## R6 · កូដដែល AI សរសេរ

*ពី [សប្ដាហ៍ទី 7 · ការរក្សាទុក និងប្រវត្តិ](notebooks/Week_07.ipynb)។*

**គោលគំនិត:** តើអ្នកអាចទុកចិត្តកូដដែល AI សរសេរបានកម្រិតណា? តើអ្នក **សាកល្បង (test)** វាដោយរបៀបណា?

- **អាន:** Python Basics ផ្នែក "07 · Function និង `return`" និង "10 · តេស្ត (test) ដោយប្រើ `assert`"។ បន្ទាប់មក ជំពូកមួយ៖ ផ្នែក "Debugging" នៃជំពូកមួយក្នុង Think Python (ឧទាហរណ៍ ជំពូក "Functions")។ ចូរប្រើ Python Tutor ដើម្បីមើល function មួយ run ម្ដងមួយបន្ទាត់។
- **សួរ (ឧទាហរណ៍):** ចូរឱ្យកិច្ចសន្យា (contract) តូចមួយទៅ AI ដូចជា *"ចូរសរសេរ Python function `average_mark(marks)` ដែល return មធ្យមភាគ (average) នៃ list ពិន្ទុមួយ ហើយ return 0 សម្រាប់ list ទទេ។ ចូរពន្យល់បន្ទាត់នីមួយៗ។"* រួចសួរបន្ត ដើម្បីសុំឧទាហរណ៍ពីជីវិតប្រចាំថ្ងៃនៅកម្ពុជា ដែលគេប្រើកូដបែបនេះ និងសួរថា *"តើមានអ្វីអាចនឹងខុសឆ្គង ចំពោះ function នេះ?"*
- **ពិនិត្យ:** ចូរសាកល្បង function របស់ AI ជាមួយ **ករណីផ្ទាល់ខ្លួនរបស់អ្នក** ដែលសរសេរជាបន្ទាត់ `assert`៖ ករណីធម្មតាមួយ ករណីព្រំដែនមួយ និងករណីចម្លែកមួយ (ឧទាហរណ៍ list ទទេ)។ ចូរបង្ហាញករណីនីមួយៗ និងលទ្ធផលរបស់វា។ តើ function នោះជាប់គ្រប់ករណីឬទេ? ប្រសិនបើមិនជាប់ តើករណីមួយណាដែលចាប់បានបញ្ហា? ចូរបិទភ្ជាប់ (paste) function នោះទៅក្នុង Python Tutor ហើយតាមដានករណីមួយ។
- **មតិរបស់អ្នក:** *តើនរណាជាអ្នកទទួលខុសត្រូវ នៅពេលកូដដែល AI សរសេរ ធ្វើឱ្យនរណាម្នាក់រងផលប៉ះពាល់?*

## ការប្រើឧបករណ៍ AI សម្រាប់ការស្រាវជ្រាវ

- **R1 និង R2:** អ្នកអាចប្រើឧបករណ៍ AI បាន ប៉ុន្តែមិនចាំបាច់ទេ។ ប្រសិនបើអ្នកប្រើវា សូមបង្ហាញកន្លែងមួយដែលអ្នកបានពិនិត្យ ឬកែតម្រូវវា ហើយប្រាប់ថាអ្នកធ្វើដោយរបៀបណា។ អ្នកអាចទទួលបានពិន្ទុពេញ ដោយមិនប្រើ AI ក៏បាន។
- **R3–R6:** អ្នកអានជាមុនសិន (ជំហានទី 1)។ ការសន្ទនាជាមួយ AI មក **ក្រោយ** ការអាន (ជំហានទី 2) ហើយវាជាផ្នែកមួយនៃកិច្ចការ។ ការប្រៀបធៀប និងពិនិត្យអ្វីដែល AI បាននិយាយ គឺជាជំហានទី 3។ AI ជួយឱ្យអ្នកយល់ ប៉ុន្តែវាមិនសរសេរសេចក្ដីសង្ខេប ឬមតិរបស់អ្នក ជំនួសអ្នកទេ។ ជំហានទី 1 និងទី 4 ត្រូវតែជាពាក្យរបស់អ្នកផ្ទាល់។ **មិនអាចប្រើ AI បានទេ?** ចូរសួរមិត្តរួមថ្នាក់ ឬគ្រូជំនួសវិញ ហើយរក្សាទុកបន្ទាត់សំខាន់ៗ 6–10 បន្ទាត់ នៃការសន្ទនានោះ តាមរបៀបដដែល។ ឬចូរសរសេរសំណួរដែលអ្នកចង់សួរ រួចឆ្លើយវាដោយប្រើជំពូកសៀវភៅទីពីរ។ វិធីទាំងពីរនេះទទួលបានពិន្ទុដូចគ្នា។

ក្នុងគ្រប់កិច្ចការ អ្វីដែលអ្នកដាក់ស្នើ ត្រូវតែជាការពន្យល់ផ្ទាល់ខ្លួនរបស់អ្នក ហើយអ្នកត្រូវតែអាចពន្យល់វាបាននៅក្នុងថ្នាក់។
