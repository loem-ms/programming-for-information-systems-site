# Local question and change review

For a shared question, use the [GitHub Issues question guide](CLASS_QA.md): record the week, input, expected result, observed result and agreed explanation. Keep a local note if offline and follow up during class or through the separately announced private contact route. Use this sheet for project review evidence. Keep a working copy and backup; the approved private submission route will be announced before work is due.

For a proposed improvement, record:

| Field | What to write |
|---|---|
| Stakeholder | Volunteer, donor liaison or community partner coordinator |
| Need | A specific decision that is difficult now |
| Before / after | Observable behavior, with units and lifecycle stage |
| Acceptance cases | At least two inputs and independently expected outcomes |
| Reproduction | Starting data, working directory, command or notebook run order |
| Peer finding | Observed output/state and its difference from expectation |
| Revision | What changed, why, and the retest result |
| Limitation | What the evidence does not establish |

Example need: a coordinator wants to see accepted reservations still awaiting collection. A list of reserved pickups is not a delivered-food report. Test both a pending reservation and one with a collection event. This is an illustrative scope, not the only eligible project.

Exchange the notebook or files with a peer and preserve their observed evidence. Use invented data and keep assessed work out of shared Issues. Follow the approved private submission instructions once announced.
