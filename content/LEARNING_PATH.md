# Weekly learning path: what to do and when to stop

The weekly slides and notebooks share three sessions: Python foundations, hands-on practice, and project studio. Each weekly notebook contains the full lesson and exercises; follow Start → Sessions 1–3 → Finish. Use this page to separate the work you must complete from the files and examples that are already provided. Each weekly notebook repeats the same guidance near the top.

## One simple rule

1. Open the current week’s notebook. Weeks 1–2 start directly; Weeks 3–10 restore embedded support files when you run setup.
2. Use the supplied starter, programs, data, diagrams and examples. You are not expected to rebuild that infrastructure.
3. Complete the short core Python experiments in the same notebook: predict, run, change and repair, then explain the concept. Continue to the separate **project or assessment evidence** below. Be ready to explain the result.
4. Save your notebook and any files you created, plus a backup. Then stop. Optional extensions can wait.

Research briefs are assigned in Weeks 1–2 and 4–7. Use the supplied reading card. Research Assignment 2 is shared in Week 3. Week 4 has no research submission or presentation; Research Assignment 3 is released after the Midterm. Week 8 closes Research Assignment 6, then shifts to the project proposal. Weeks 9–10 contain no research obligation. If setup, access or an unclear instruction blocks you, record the exact point and ask for help.

## Optional syntax lookup

[Python Basics](learning_materials/Python_Basics.ipynb) is an optional quick lookup with 19 short syntax topics and small examples. Required explanations and Python exercises are in each weekly notebook. Look up a topic only when needed, then return to the same weekly task; return to the weekly notebook after checking the syntax.

The weekly slide PDF is a teaching and review aid. The notebook’s labelled required task is the work to complete. “Further reading” and optional AI/live-model activities are not required for assessment.

## Saving now and submitting later

Keep your edited notebook, any program/data files you created and the evidence named above. Make a separate backup before replacing course files or ending a Colab runtime. Send submissions to [submit.progmis@gmail.com](mailto:submit.progmis@gmail.com). The file-naming rule will be announced before work is due. Do not post complete assessed work in GitHub Issues.
